## 🌟 Visão Geral

<details>
<summary>▶️ <strong>Clique para expandir / recolher esta seção</strong></summary>

**Trabalhos-do-Curso** reúne o trabalho produzido em uma disciplina de desenvolvimento web: um site estático de duas páginas para a **SECURITY HELP**, uma consultoria fictícia de segurança da informação. O site é escrito à mão em **HTML5**, **CSS3** e **JavaScript puro**, sem framework, bundler, gerenciador de pacotes ou qualquer código de servidor.

A página inicial (`index.html`) é um único documento longo, rolável, dividido em seções endereçáveis por âncora (Home, Serviços, Cases de Sucesso, Equipe), acessadas a partir de uma barra de navegação fixa. Uma segunda página (`fale_conosco.html`) hospeda um formulário de contato com validação simples no lado do cliente. O repositório também contém um arquivo `trabalho_des_web.zip`, que é o entregável empacotado submetido para avaliação, além de três arquivos `new.txt` que marcam pastas de assets vazias no versionamento.

Como o projeto é um trabalho acadêmico, o "negócio" documentado (SECURITY HELP, seus 37 funcionários listados, seus depoimentos) é conteúdo fictício criado para atender a um enunciado. Este README trata o projeto como qualquer outro artefato de software: a estrutura, a estilização e a interatividade são reais e documentadas como foram construídas.

### 🎯 Objetivos do Sistema

| Objetivo | Descrição |
|-----------|-------------|
| 🏠 **Página Inicial** | Apresentar a empresa fictícia em um único `index.html` rolável |
| 🧭 **Navegação por Âncora** | Permitir que o visitante pule para `#home`, `#servicos`, `#cases_sucesso`, `#equipe` a partir de um cabeçalho fixo |
| 🛡️ **Catálogo de Serviços** | Descrever quatro linhas de serviço de segurança da informação em lista |
| ⭐ **Prova Social** | Exibir cinco depoimentos de clientes em "Cases de Sucesso" |
| 👥 **Diretório de Equipe** | Listar o quadro fictício de funcionários em duas colunas |
| 📨 **Formulário de Contato** | Coletar nome, e-mail, data de nascimento e mensagem em `fale_conosco.html` |
| 🎨 **Layout Responsivo** | Adaptar as colunas de equipe e serviços para telas abaixo de 800px |
| 🔗 **Links Sociais** | Apontar para Facebook, Instagram e WhatsApp no rodapé |

## 🎨 Padrões de Projeto Aplicados

<details>
<summary>▶️ <strong>Clique para expandir / recolher esta seção</strong></summary>

| Padrão | Onde | Justificativa |
|---------|-------|-----------|
| 🧭 **Navegação por Fragmento** | `<a class="menu" href="#servicos">` etc. | Saltos por âncora na mesma página evitam carregamentos extras para conteúdo relacionado |
| 🗂️ **Seção-como-Componente** | `<div class="img_home">`, `.img_servicos`, `.img_cases_sucesso`, `.equipe` | Cada bloco visual é um par autocontido de marcação + classe CSS |
| 🎭 **Wrapper de Imagem de Fundo** | `.img_home`, `.img_servicos`, `.img_cases_sucesso` | Uma `div` externa fornece a foto de fundo; uma `div` interna contém o texto legível |
| 📐 **Divisão em Duas Colunas** | `.equipe1` / `.equipe2` (baseado em float) | O quadro de 37 pessoas é balanceado em duas listas flutuantes |
| 📱 **Enriquecimento Progressivo (breakpoint)** | `@media(max-width:800px)` em `style.css` | Colunas de equipe e serviços colapsam para largura total em telas pequenas |
| ✅ **Validação por Cláusula de Guarda** | `enviar()` em `complemento.js` | `if`s aninhados rejeitam entradas vazias ou malformadas antes de alertar sucesso |
| 🏷️ **Marcos Semânticos** | `<header>`, `<nav>`, `<footer>` | Elementos nativos de landmark do HTML5 estruturam a página em vez de `div`s genéricas |

### 🧭 Cabeçalho & Navegação

Presente de forma idêntica no topo de ambas as páginas. Um `<header><nav>` envolve uma `div.navegacao` contendo a imagem do logo e quatro ou cinco links de menu.

| Elemento | `index.html` | `fale_conosco.html` |
|---------|--------------|----------------------|
| Logo | `<img src="img/logo.png">` | `<img src="img/logo.png">` |
| HOME | `href="#home"` | `href="index.html"` |
| SERVIÇOS | `href="#servicos"` | `href="index.html"` |
| CASES DE SUCESSO | `href="#cases_sucesso"` | `href="index.html"` |
| EQUIPE | `href="#equipe"` | `href="index.html"` |
| CONTATO | `href="fale_conosco.html"` | `href="#contato"` |

> [!NOTE]
> Em `fale_conosco.html`, o link CONTATO aponta para `#contato`, mas nenhum elemento do arquivo possui `id="contato"` — a âncora atualmente resolve para o topo da página.

---

### 🏠 Seção Home

`div.img_home` (fundo de tela cheia a partir de `img/home.jpg`, fixo) envolve `div.home#home`, que contém um `<h1>APRESENTAÇÃO</h1>` e um parágrafo justificado apresentando a SECURITY HELP: fundada em Irati-PR, cinco filiais no Paraná, mais de 20 anos de mercado.

---

### 🛠️ Seção Serviços

`div.img_servicos` dispõe `div.servicos#servicos` (40% de largura, inline-block) ao lado de `div.servicos2` (um painel de imagem posicionado de forma absoluta mostrando `img/servicos.png`). A lista de serviços (`<ul><li>`) enumera quatro ofertas:

| # | Serviço | Resumo |
|---|---------|---------|
| 1 | Análise de Vulnerabilidade em T.I | Varre dispositivos/redes em busca de fraquezas, usando técnicas como "Pen Test" |
| 2 | Políticas de Segurança da Informação | Tratamento conforme LGPD, com certificações ISO 27001 e ISO 27002 citadas |
| 3 | Recuperação de Dados | Plano de Backup e Continuidade de Negócios: 3 backups em 2 mídias diferentes |
| 4 | Capacitação, Certificação e Treinamento | Certificação e treinamento alinhados à LGPD, ISO 27001/27002 |

---

### ⭐ Seção Cases de Sucesso

`div.img_cases_sucesso` (fundo `img/cases_sucesso.jpg`) envolve `div.cases_sucesso#cases_sucesso`, contendo um `<h1>` e cinco pares `<h4>`/`<p>` de depoimentos de clientes fictícios, além de um parágrafo final afirmando mais de 350 empresas parceiras.

| Cliente | Domínio |
|--------|--------|
| Banco Socorro | Bancário |
| Ministério Público | Setor público |
| Só Fast, Só Food | Delivery de comida |
| FlashSpeed | Mobilidade urbana |
| ChatBook | Mensageria/social |

---

### 👥 Seção Equipe

`div.equipe#equipe` (fundo claro, texto escuro via override inline) contém um parágrafo introdutório seguido de duas listas não ordenadas flutuantes, `equipe1` e `equipe2`, cada uma com cerca de 18-19 itens `<li>` de `Nome - CARGO`, totalizando **37 funcionários nomeados** em cargos como Analista de Segurança, Engenheiro de Redes, Consultor Cibernético. Um parágrafo final afirma que a empresa emprega 100 pessoas ao todo.

---

### 📨 Página de Contato

`fale_conosco.html` reutiliza o mesmo header/nav e apresenta um `<form name="formulario">` simples (sem `id`, sem `action`, sem `method`) com quatro campos.

| Campo | Tipo de input | Obrigatório | Notas |
|-------|-----------|----------|-------|
| `nome` | `text` | ✅ | Nome completo |
| `email` | `email` | ✅ | Checagem nativa do navegador para formato de e-mail |
| `datanasc` | `date` | — | Data de nascimento, opcional, `id` referenciado mas sem `for` correspondente no label |
| `mensagem` | `textarea` (30×10) | ✅ | Mensagem livre |
| submit | `input[type=submit]` | — | `onclick="Enviar()"` (E maiúsculo — não corresponde a nenhuma função definida) |

O documento também declara um `<script>` inline com `enviarFormulario()`, que reseta `#meuFormulario` (um id que o formulário não possui de fato) e chama uma linha malformada `document.getElementById(...).prompt(...)`. Nem essa função inline nem `Enviar()` (com maiúscula) são efetivamente invocadas pela marcação atual; ver [Limitações Conhecidas](#-limitações-conhecidas).

---

### 🦶 Rodapé

Presente em ambas as páginas: um título `<h3>CONTATOS E REDES SOCIAIS</h3>` seguido de `div.rodape` com links de ícones para Facebook, Instagram e WhatsApp, além de um link de atribuição ao Flaticon envolvendo a imagem do logo (satisfazendo a licença do ícone).

## 🔐 Segurança

<details>
<summary>▶️ <strong>Clique para expandir / recolher esta seção</strong></summary>

### Controles Implementados

| Controle | Implementação | Efeito |
|---------|---------------|--------|
| ✅ **Atributos HTML5 required** | `required` em `nome`, `email`, `mensagem` | Navegador bloqueia envio vazio antes de qualquer script rodar |
| 📧 **Validação nativa de tipo e-mail** | `type="email"` no campo de e-mail | Navegador impõe um formato básico de endereço |
| 🚫 **Sem credenciais inline** | Nenhuma chave de API, token ou segredo em qualquer lugar do código | Nada sensível a vazar de uma página estática |
| 🔒 **Sem inclusão de scripts externos** | Toda referência `<script>`/`<link>` é do mesmo domínio | Nenhuma superfície de cadeia de suprimentos de terceiros |
| 🧾 **Template de segredos no `.gitignore`** | O `.gitignore` raiz exclui `.env`, `*.pem`, `*.key`, arquivos de credenciais | Protege contra commits acidentais de segredos futuros |

### Limitações de Segurança Conhecidas

> [!WARNING]
> Este é um site estático de trabalho acadêmico, sem backend; os itens abaixo descrevem lacunas em relação a um formulário de contato de produção, não explorações ativas.

| Limitação | Risco | Caminho de mitigação |
|------------|------|-----------------|
| 📭 **Sem `action`/`method` no formulário** | Enviar `fale_conosco.html` atualmente recarrega a página com query params em vez de atingir um endpoint de servidor | Adicionar um `action` real apontando para um backend ou serviço de formulário |
| 🧪 **Validação apenas no cliente** | As checagens de `enviar()` são trivialmente contornáveis (desabilitar JS, ou fazer POST diretamente) | Qualquer deploy real deve validar novamente no servidor |
| 🪪 **Referência de função quebrada** | `onclick="Enviar()"` nunca corresponde à definição em minúsculas `enviar()` | Corrigir a capitalização para que a checagem pretendida realmente rode |
| 🔗 **Tag de stylesheet incorretamente ligada ao JS** | `index.html` carrega `js/complemento.js` via `<link rel="stylesheet">` | Deveria ser uma tag `<script src="js/complemento.js">` |
| 🖊️ **Sem codificação de saída necessária hoje, mas nenhuma definida** | Se o formulário for algum dia conectado para renderizar conteúdo enviado de volta, não há sanitização em vigor | Codificar/escapar qualquer entrada do usuário antes de renderizá-la, caso um backend seja adicionado |
| 🍪 **Sem token CSRF** | Qualquer futuro endpoint POST aceitaria hoje envios forjados | Adicionar um token CSRF assim que um backend real existir |

## ⚠️ Limitações Conhecidas

<details>
<summary>▶️ <strong>Clique para expandir / recolher esta seção</strong></summary>

> [!IMPORTANT]
> Este projeto foi construído como trabalho de faculdade de desenvolvimento web para praticar estrutura HTML, layout CSS e manipulação básica de formulário em JS. Não foi construído para deploy em produção.

| Categoria | Problema | Status |
|----------|-------|--------|
| 🔗 **Tag de script mal ligada** | `index.html` inclui `js/complemento.js` via `<link rel="stylesheet">` em vez de `<script src>` | ⚠️ Aberto |
| 🔤 **Divergência de maiúsculas no nome da função** | `onclick="Enviar()"` em `fale_conosco.html` nunca corresponde à `enviar()` minúscula em `complemento.js` | ⚠️ Aberto |
| 🆔 **Script inline malformado** | `enviarFormulario()` reseta um `#meuFormulario` inexistente e chama `.prompt(...)` no retorno de `getElementById(enviarFormulario())`, o que é inválido | ⚠️ Aberto |
| 🎯 **Âncora `#contato` sem destino** | O link CONTATO na página de contato aponta para `#contato`, que não possui `id` correspondente | ⚠️ Aberto |
| 📭 **Sem backend de formulário** | O formulário de contato não tem `action`/`method`, então os envios não são de fato enviados a lugar nenhum | ⚠️ Aberto |
| 🏷️ **Texto `alt` genérico** | Várias imagens usam `alt="icon"` em vez de uma descrição específica daquela imagem | ⚠️ Aberto |
| 🌍 **Apenas um idioma** | O conteúdo do site é somente em português; não há mecanismo de localização na própria marcação | ➕ Intencional — escopo de trabalho acadêmico |
| 🧪 **Sem testes automatizados** | Nenhum test runner ou CI configurado | ⚠️ Aberto |
| 📦 **Header/nav/rodapé duplicados** | Repetidos à mão em ambos os arquivos HTML em vez de templatizados | ➕ Intencional — nenhum motor de templates faz parte do enunciado |
| 🗂️ **Placeholders `new.txt`** | `css/new.txt`, `js/new.txt`, `img/new.txt` existem apenas para manter pastas vazias rastreadas pelo Git | ➕ Intencional |

> [!TIP]
> A correção de maior valor é resolver a divergência `enviar()`/`Enviar()` e conectar `complemento.js` com uma tag `<script src="js/complemento.js">` adequada, já que essa única mudança faz a lógica de validação existente rodar de verdade pela primeira vez.
